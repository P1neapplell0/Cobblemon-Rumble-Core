# ArcQuest 剧情规范

- 先核对 ArcQuest 开发文档、当前依赖源码、旧核心的同类章节，再确定 quest、phase、dialogue 和 actor ID。用 `QuestBuilder` / `PhaseBuilder` 和 `DialogueTreeBuilder` 构建，阶段 ID 对应具体玩家目标。主线 `ARCHON`、`champion_road`、金色；支线 `ADVENTURE`、`adventure_quests`、蓝色。可交互 NPC、石碑、抵达点使用 ArcQuest `trackingMarker`，记录维度和坐标。任务接取用紫色提示窗，不加 splash。一次发放多条任务时，先主线、后支线；让接取时的自动追踪最终落在支线上。路标颜色与任务主题色一致。
- 互动始终经服务端检查 NPC 身份、维度、距离、视线和当前阶段；跟踪支线专属选项用绿色，提交前重查背包并只扣一次。物品提示用 `quest/RewardNotice`，发放和展示使用同一份注册 `ItemStack`；领奖用阶段或玩家标记防重，测试关对话重开、重登和缺物品分支。未发布的剧情改动不加存档迁移或旧状态回填。
- NPC 资源按稳定的角色 aspect 绑定皮肤、poser 和动画，位置记在 `GymCatalog` 或剧情场景类。多人对话分别绑定说话人和 ArcQuest 摄像机目标，按节点切换，查 `ProfessorRestock`、`GymDialogueCamera` 和 `QuarkProfessorGesture`。按性格给节点选 `wave`、`think`、`point`、`yes` 等 Quark 表情，仅为本节点实际说话人播放；Quark 未装时保持正常对话和运镜。演出、说话人朝向和运镜按观看者处理，不把单人剧情写到共享实体上。
- UI、对白、任务目标均给中英语言键。奖励明确播放的节点及多人运镜都要在实机验证；用独立存档，截图和指南按 [指南检查项](arcquest-guides.md#新指南检查项) 处理。
- 前三馆的对战、馆主战后对白和回访是同一条主线的连续阶段。徽章及对战奖励在对战阶段结算，下一馆等回访结束再接取。MineChat 插曲按玩家发一次，不参与任务完成判定。
- 女性 NPC 的外观预设集中在 `TrainerGenderLayer`；道馆角色按角色 ID 稳定分配 B–D，小瑶固定用 B。客户端没装性别模组时用普通 Alex 模型。
- 「Mega 进化特训」在第三馆回访后接取，放在下一馆主线之后。合成阶段同时核对合成产物的 Mega 装置标签和格子里的钥石；模拟阶段只认副本 `Completed` 结算名单。小瑶的教学战沿用独立竞技场，对战中每位玩家只占用一个 Mega 位，换将不恢复次数。胜利后回访结算，战败或退出可重开。
- Mega 模拟配队和奖励直接维护在 `modpack_override/config/cobblemon_rumble_core/mega_challenges.tsv`。列依次为挑战 ID、物种、形态、基础外观、等级、性格、六项努力值、四个招式、奖励物品、宝可币和配队来源。小瑶剧情队伍独立定义在 `GymTeamPokemon.may()`；修改后用隔离服核对实际生成的形态、道具和招式。


## 旧核心 ArcQuest 改动对照

当前已接入接取时的紫色通知和自动追踪、后台目标或阶段变化后的追踪、任务主题色路标、隐藏已失败页和放弃任务按钮，以及 `cobblemon:gui.click` 界面音效。

| 旧功能 | Rumble Core 现状 |
| --- | --- |
| 对白指定空白说话人、自动拆分长对白、调试跳过对白 | 三项定制未迁移。 |
| 传奇演出的距离豁免、风暴神末句延时和说话人交接 | 旧剧情专用逻辑未迁移。 |
| 管理员给任务／跳阶段时绕过前置、传奇专属接取规则、二周目与仅展示奖励 | 旧规则未迁移。ArcQuest 1.0.14 提供接取和奖励规则扩展点。 |
| 任务详情的开场重播与二周目入口、开场对白里的博士立绘、自由模式批量解锁时抑制指南弹窗 | 四项界面定制未迁移。 |
| 路标使用实体实时名称、只显示追踪任务及旧主线所选并行阶段的路标、骑乘相机投影 | 旧过滤和投影逻辑未迁移。ArcQuest 1.0.14 提供路标外观、可见性和相机基向量扩展点。 |
| 无任务追踪时，靠近路标自动选择任务并播放提示 | 未迁移。 |
| WebSocket 停服竞态、对白日志快照编码、放弃单个可选阶段 | ArcQuest 1.0.14 已在上游提供对应修复或 API。 |

当前对话朝向由 `DialogueActorPose` 在客户端渲染时插值。头部响应快于身体，会话结束后回到实体的待机姿势。每位观看者独立计算对话朝向。

### 冠军终章

- 八馆首胜完成后接取主线 `champion_battle`。博士说明挑战后，稍后再战也会推进到备战阶段，可以重新交谈开战。`rumble_champion` 仅接受发起人的单人场次。正式胜利结算推进到名人堂，对话后播放过场，客户端确认后再接取常驻结语 `champion_finale`。
- 名人堂沿用冠军副本的个人排行榜。结算时保存每位参与者的原始队伍及实际派出的宝可梦详情，随对应最佳场次读取。副本内拦截玩家发起的队伍编辑请求，神兽捕捉继续走 Cobblemon 原生入队及入 PC 流程。
- 名人堂画面参考 [HTML 原型](hall-of-fame/index.html)。暂停菜单和启动封面的样式、推荐链接维护在 `client/menu/PackMenus`，文本维护在中英语言文件中。
- 在游戏内以 OP 权限执行 `/rumble halloffame preview` 可重播完整入场效果。预览使用当前队伍，空队伍时显示六只示例宝可梦，不修改任务、队伍或排行榜。
