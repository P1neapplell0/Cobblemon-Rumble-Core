# 实时战斗特殊机制过场

- 太晶化、Mega、极巨／超极巨及 Z 招式通过各自的原始合法性检查后，才开始过场。过场使用 Cobblemon Cinematics 1.4.0 的同类演出。结束后服务器执行变身或发起原有的 Z 招式攻击；原有道具、场地和次数规则不变。
- 在副本内，同场参战玩家都收到同一个过场（包括 PvP 的对手）。期间冻结参战角色和 AI、拦截移动及战斗输入，并保护双方免伤；红蓝计时赛不扣除演出时间。野外只暂停当前操控者及与其已交战的野生宝可梦，不停服。
- 过场长度由服务器设下限和硬超时（标称 5.6 秒，最多 160 个服务器刻）；客户端完成通知不具有提交变身的权限。失去操控对象、发起方退出或副本结束，取消未执行的变化并清理锁定。
- Cinematics 是客户端可选依赖。至少一名参战客户端声明安装后，才启动同步过场；同场没有该模组的玩家看到简版提示。全场都没装时保持原行为。

## 更新依赖时

- `RealtimeGimmickPresentation` 和 `GimmickCinematicScreen.Backend` 适配 Cinematics 1.4.0 的私有管理器。升级时检查 `enqueue`、`render`、`findTrainerId`、`tick` 的界面判定，以及 5600 ms 时间轴；上游若提供实时战斗播放入口，替换这一层即可，不需改服务端战斗逻辑。
- `GimmickCinematicHooks` 与 `RealtimeMoveWindupZInput` 适配 RealtimeCobblemon 1.0.3alpha.1 的已验证激活点。升级时核对 Mega／极巨的原始前摇值（60／40 刻）及 Z 招式消费标记的写入点。Z 招式的场内出招与命中判定仍由 RTC 负责。
