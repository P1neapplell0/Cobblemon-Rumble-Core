# 实时玩法与兼容维护

## 战斗与收服

- 训练师直接近战攻击宝可梦会在攻击流程开始前被服务端取消；箭、三叉戟及其他归属于玩家的伤害也会被拦截，并在快捷栏上方显示“训练师要堂堂正正的战斗！”。实现位于 combat/PlayerPokemonAttackGate；RTC 以宝可梦实体为来源的招式保留，不影响玩家攻击其他生物。

- 对准野生宝可梦按 Cobblemon 的派出／战斗键（默认 R），通过原 `BattleChallengePacket` 在服务端校验目标与队伍选择，再进入实时战斗。伙伴未派出时等待派出动画完成；已在跟随时直接进入。对空地或自己的伙伴按键仍走普通派出／收回，允许正常跟随。后续收回、目标失效、离线、换维度会使等待中的挑战失效。RTC 原生切换键（默认 V）保留进入／退出操控功能，可以直接接管已派出跟随的伙伴。原派出键不再与 RTC 锁定键同时执行收回。
- 回合制入口统一禁用；NPC 和玩家挑战暂不接入实时对手规则。
- 玩家投球不再收服。实时对战击倒可捕捉野生宝可梦后，每只独立复制、恢复血量、直接存入电脑，不扫描或升级已有同类，队伍有空位也不自动入队。电脑满时提示保存失败。原有电脑界面保持上游行为，已移除额外的全仓搜索、筛选和排序。
- 野生击败仍按最大 HP 结算宝可币（1 HP = 1 币），提示实际到账额。玩家所有、决斗和诱饵目标不参与野生结算。结算标记仅防止同一只被多个命中回调重复计奖，不影响同物种再次捕捉。
- 收服复用 PC 存储及 `POKEMON_GAINED` 图鉴通知；没有投球实体，不发送依赖球实体的 `POKEMON_CAPTURED` 事件。

## 相机

- `client/combat/StableBattleCamera` 在渲染帧读取插值后的身体与目标位置，使用纳秒时钟。自由鼠标转向即时响应，水平镜头直接跟随渲染身体以消除启动／刹车时的漂移；锁定朝向仅做一层快速阻尼，垂直跟随略慢以吸收台阶跳动。移除原相机的步态起伏和每 tick 速度前瞻。
- 相机位置计算后做八点体积碰撞检测，遇墙立即缩短镜头臂，离墙以阻尼恢复；暂停冻结阻尼，长帧、传送、换世界或控制对象后重置状态。保留左右肩、对峙和招式特写。
- `mixin/minecraft/BattleViewBobbing` 在 RTC 第三人称操控期间屏蔽原版的走路视图矩阵晃动，正常跟随和普通玩家视角仍遵循游戏设置。准星使用实体渲染器同一组 `xOld/yOld/zOld` 插值位置及相机的帧时间。`ReticleProjection` 读取当前帧实际视图／投影矩阵，世界坐标先相减、投影及 GUI 偏移保持 double；`SubpixelBattleReticle` 补回上游 GUI 整数取整丢掉的小数位置，中心点对齐投影点，边缘用物理像素覆盖率实现平滑移动。服务端命中规则不变。

设计参考 Unity Cinemachine Third Person Follow 的分轴阻尼、肩位枢轴和碰撞恢复思路，参数与实现针对 RTC 的玩家代理身体重新编写；保留即时自由转向，并对模式切换做短暂混合。镜头角度、轨道方向使用 double 和连续三角函数，仅在调用 Minecraft 相机旋转接口时转 float，避免查表方向量化。参考文档：`https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachineThirdPersonFollow.html`。

## 手机与钱包

- 首次登录会发一部红色智能手机。右键应用 SD 卡，解锁记录保存到玩家而不是手机；更换手机或死亡不会丢失。空白卡和已有应用卡的模型保留，重复使用不会扣卡。
- 自然指南针、结构指南针改接手机原生 GPS／结构搜索；PC、治疗、图鉴、传送石碑、追踪、垂钓和 MineChat 在对应依赖和配置可用时开放。云存储安装 Beyond Dimensions 时打开其网络，否则走手机原生末影箱。究极空间卡保留物品，但不安装应用（目前未启用对应模组）。预留手机商人及发卡来源。
- 旧核心的钱包界面迁入了背包余额、银行价目表以及商店搜索、库存和价格显示，购买数量受库存、余额和背包容量约束。

## 配置与源码位置

- 开发端和服务端的 `config/cobblemon/main.json` 已对齐旧核心中仍适用的设置，包括治疗仪无限电量 `infiniteHealerCharge=true`、箱数、经验分享、每区块刷怪量、牧场距离、扫描距离、未知宝可梦名称及骑乘。新配置由 `mixin/cobblemon/combat/CobblemonDefaults` 提供这些默认值；其他已有部署如保留旧 JSON，需将治疗仪字段改为 `true` 并重启。原世界已有的电脑容量不因默认箱数改动而自动改变。
- Mixin 按实际被注入的目标模组 ID 存放在 `mixin/<mod_id>/`。挑战入口在 `combat/RealtimeBattleEntry`，击败结算在 `combat/reward/`，相机及渲染射线在 `client/combat/`，应用权限在 `phone/`，钱包与界面在 `wallet/` 和 `client/bank/`。
- 升级模组时优先核对：Cobblemon `ChallengeHandler`、`SendOutPokemonHandler`、`BattleRegistry`；Real-Time `MoveEngine` 调用的 `Experience.knockedOut`、`BattleCamera` 的 `place/aimPoint/onRenderLevel`；Smartphone 服务端原生包以及 datapack 函数分派。相机主体在 `StableBattleCamera`；锁定与自由准星使用渲染帧位置，逻辑侧命中不受影响。

## 回归检查（2026-11-17）

隔离 NeoForge 测试世界已验证：

1. 普通派出后实体留在场上、服务端和客户端均未进入 RTC；V 可正常进入并退出操控。
2. 伙伴已在跟随时，挑战野生目标会复用伙伴的同一实体；伙伴未派出时等动画完成再进入。挑战自身、无效目标及派出动画期间取消均不会错误开战。
3. 连续击败 10、22、18 级伊布，电脑新增三个不同 UUID 的个体并保留各自等级，队伍空位不被占用；同一击败重复回调不重复收服或发币。
4. 实际客户端分别在自由、锁定和对峙视角下持续左右移动；锁定阶段额外检查目标没有丢失。静止时单独改变步态和 tick 速度不再改变镜头位置。
5. 强制非零步态后调用实际渲染器，确认 RTC 中原版走路晃动被屏蔽；30、60、144 FPS 的阻尼收敛结果一致；放置测试墙后镜头留在墙外，移墙后逐渐恢复。
6. GUI 缩放 1～4 各截取两张实际准星画面；每次移动 0.1 GUI 单位，物理像素位移分别约为 0.1、0.2、0.3、0.4。八张截图的亮度重心与投影中心误差均小于 0.002 像素，包括窗口尺寸不能被缩放倍率整除的情况。大世界坐标投影及同帧矩阵对照检查通过。

人工复查时保留游戏的「视角摇晃」开启，分别测试普通步行、跟随、空地派出、对野生目标发起挑战、锁定横移、近墙绕行和退出操控。这样可同时确认战斗镜头稳定，以及普通游戏视角的设置未受影响。
